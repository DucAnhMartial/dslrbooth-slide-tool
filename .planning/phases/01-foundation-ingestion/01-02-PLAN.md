<objective>
Complete webhook authentication on top of the proven tracer: durable replay protection,
timestamp freshness, a single generic denial path, and a hardened IP allow-list that cannot be
bypassed by a forged forwarding header.

Purpose: the tracer proved a signature can be verified. On its own that still lets an attacker
who captured one valid request replay it forever, and lets a client on a non-allow-listed
socket claim an allow-listed address in a header. This plan closes both.

Output: `webhook_replay` SQLite table + store methods, `isTimestampFresh()` /
`checkWebhookAuth()` in `webhookAuth.ts`, extended auth tests, and a persistence test proving
replay and cursor state survive a restart.

**Repository note:** all git operations must be run inside `mirror-request/`; the workspace
root is not a git repository.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet -> reverse proxy -> Express | Attacker controls all request headers, including any forwarding header |
| Captured valid request -> replayed request | A previously-legitimate signed request is attacker-controlled once observed |
| Process memory -> PM2 restart | Any state not in SQLite is lost on a routine deploy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Spoofing | replay of a captured signed `POST /on-register` | high | mitigate | `checkWebhookAuth()` rejects any `X-Webhook-Id` already present in `webhook_replay`; the id is recorded only after full authentication (task 2) |
| T-01-09 | Spoofing | stale or future-dated `X-Webhook-Timestamp` | high | mitigate | Symmetric `isTimestampFresh()` window bounded by `WEBHOOK_TIMESTAMP_SKEW_MS` (default 300000) (task 2) |
| T-01-10 | Spoofing | forged forwarding header claiming an allow-listed source IP | high | mitigate | No Express application-level proxy-trust setting anywhere in `src`; the allow-list reads the direct socket peer only; regression test + grep gate (task 3) |
| T-01-11 | Tampering | replay state kept in process memory | high | mitigate | `webhook_replay` is a SQLite table read/written through prepared statements; a close/reopen test proves survival (task 1) |
| T-01-12 | Tampering | SQL injection through `webhook_id` | high | mitigate | `better-sqlite3` prepared statements with `?` placeholders only; no `exec()` with interpolated values (task 1) |
| T-01-13 | Information Disclosure | denial response or log reveals which check failed | medium | mitigate | One denial branch, one generic log string, response body asserted to contain only `error: 'Forbidden'` (task 2) |
| T-01-14 | Denial of Service | unbounded `webhook_replay` growth over the service lifetime | low | accept | D-14 makes retention manual; single-booth volume makes this a multi-year non-issue (RESEARCH.md A4). Revisit if a retention-tooling phase is scheduled. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan; RESEARCH.md `## Package Legitimacy Audit` covers the only two Phase 1 packages, both verdict OK / Approved with no `[ASSUMED]`/`[SUS]`/`[SLOP]` entries |
</threat_model>
