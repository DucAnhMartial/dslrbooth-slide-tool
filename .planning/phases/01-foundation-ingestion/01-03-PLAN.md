<objective>
Make the read-only DB polling fallback resilient and observable: typed configuration instead
of stray `process.env` reads, a warning-and-retry failure posture that cannot take the service
down or permanently stop polling, an informational reconciliation log when the poller meets a
registration the webhook already ingested, and an audit log for unusable source rows that
still lets the cursor move.

Purpose: polling is the safety net for ING-01. Today a first-cycle failure sets
`this.running = false` and polling never resumes until a restart, and an already-processed
record is skipped in complete silence — so the safety net can fail silently in both
directions.

Output: a `DBPoller` that takes its database settings as a constructor argument, four
explicit log branches, and a unit test suite driven by a mocked `mysql2/promise` pool.

**Repository note:** all git operations must be run inside `mirror-request/`; the workspace
root is not a git repository.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External MySQL `registrations` table -> DBPoller | A foreign-owned database supplies rows this service treats as registrations |
| DBPoller -> structured log files | Poller output can carry credentials or guest PII if written carelessly |
