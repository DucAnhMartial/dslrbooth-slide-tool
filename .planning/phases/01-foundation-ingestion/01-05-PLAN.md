  <how-to-verify>
    **1. HMAC canonical string (RESEARCH.md Open Question 1 / assumption A1 — D-09, D-10)**

    This service computes the expected signature over
    `` `${X-Webhook-Timestamp}.${X-Webhook-Id}.${rawBodyUtf8}` ``, HMAC-SHA256, hex-encoded, and
    reads `X-Webhook-Timestamp` as epoch **milliseconds**. CONTEXT.md delegated the exact choice
    to Claude, but it only works if Mirror Request signs the same way.
    - Check the Mirror Request / form-proxy signing code (or ask whoever owns it) for: the exact
      string it signs, the digest encoding (hex vs base64), and whether the timestamp is
      milliseconds or seconds.
    - If it differs, the fix is confined to `buildCanonicalString()` and `isTimestampFresh()` in
      `mirror-request/src/ingestion/webhookAuth.ts` — report the real format and it becomes a
      two-function change.
    - If Mirror Request has no signer yet, confirm that this service's format is now the contract
      and pass it to whoever builds the sender.

    **2. D-02 identity reading (RESEARCH.md Open Question 2 / assumption A2)**

    This phase read D-02's "if it is absent" as *if an `id` match is absent*, so the ladder is:
    same `id` inside the window, else same non-empty email or phone inside the window. `id`
    remains a hard-required field — a payload without one still gets `400 {error:'id and name are
    required'}`.
    - Confirm this matches your intent.
    - If you actually want `id`-less payloads accepted with identity falling back to email/phone,
      say so — that is a new decision and a follow-up plan, not a bug in this one.

    **3. Production allow-list strictness (D-09)**

    Startup now throws in production when `WEBHOOK_HMAC_SECRET` is empty, or when
    `PROXY_IP_WHITELIST` is unset or contains only `127.0.0.1`.
    - Confirm the production `.env` (or PM2 env) carries a real secret and the real reverse-proxy
      addresses before the next deploy, or the service will refuse to boot.
    - Dry run: `cd mirror-request && NODE_ENV=production npm run build && NODE_ENV=production node -e "require('./dist/config').loadConfig()"`
      should print nothing and exit 0 once the environment is right.

    **4. D-14 manual retention acknowledgement**

    Nothing in this service deletes data. `registration` (including email, phone and the raw
    payload), `webhook_replay`, `processed_id` and `queue_job` all grow without bound, by design.
    - Acknowledge that deleting operational data is the operator's job, and note where you want
      that documented if anywhere.

    **5. End-to-end smoke (ROADMAP M1 success criteria)**

    - `cd mirror-request && npm run dev` starts and logs `Extension Service ready on ...`
    - The SQLite file exists with `registration`, `queue_job`, `processed_id`, `db_poll_cursor`,
      `booth_state`, `notification_record` and `webhook_replay` tables
    - A correctly-signed `POST /on-register` returns 200; the same request from a
      non-allow-listed address returns 403
  </how-to-verify>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Guest PII in a request payload -> rotated log files on disk | Log files are longer-lived and more widely readable than the database |
| Developer debugging convenience -> production log output | Any debug affordance is a production leak unless it is gated |
| This service's signature format -> Mirror Request's signer | A contract this repository cannot verify on its own |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-28 | Information Disclosure | raw Mirror Request payload written to a production log file | high | mitigate | `debugRawPayload()` is the only route and returns early unless `NODE_ENV` is non-production AND `DEBUG` is set; asserted by tests and a grep gate (tasks 1-2, D-16) |
| T-01-29 | Information Disclosure | guest email or phone in an ingestion log line | high | mitigate | Every receiver log call passes a plain interpolated string naming ids and status only; the suite asserts `mask(msg) === msg` for every captured message (task 2, D-15, AUTH-03) |
| T-01-30 | Information Disclosure | object-argument log call bypasses the transport-level printf masking | medium | mitigate | Grep gate forbids object-literal arguments to `logger.*` in the receiver; masking only fires for string messages (task 2, RESEARCH.md Pitfall 6) |
