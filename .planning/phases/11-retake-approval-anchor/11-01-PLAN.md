<assumption_delta_decision>
The detector's `pluralization` family fires on this phase: one dslrBooth session per job becomes
many attempts per job.

- **Primary noun:** the **attempt** is now the unit that owns a composite, an approval and a
  photo URL. The **job** remains the guest-facing identity and the primary key of `queue_job` —
  it is not demoted, because nothing guest-facing is per-attempt.
- **Decision: `promote`.** The attempt is promoted into durable state (`booth_state.attempt_open`,
  `booth_state.attempt_no`, `pending_print.attempt_no`) rather than added alongside as an
  in-memory notion. The previously-implicit "one session = one job" assumption is deleted, not
  kept beside the new model: `processing_start` no longer completes anything, so there is no
  surviving code path that still treats the first composite as the guest's photo.
- **Invariant test encoding it:** the rewritten `test/queue-retake-anchor.test.ts` asserts one
  notification per JOB across N attempts. It goes red the instant a future edit reintroduces a
  per-composite send.
</assumption_delta_decision>
