<objective>
Harden the room's big screen. `WS /display` today has no access control at all and puts a
whole `queue_job` row on the wire four times a second — `stall_reason`, `retries`,
`ack_error_message` and the internal `registration_id` included — to anyone who can reach
the port. `GET /display-screen` is equally open.

This plan gates both surfaces behind an IP allow-list enforced before the handshake,
removes the leaking field by construction rather than by a null check, replaces the
unconditional 250 ms broadcast with a change-driven one, projects up-next names down to
given names, and injects the store so the display path stops reaching for the module-scope
singleton.

Purpose: these five concerns all land in the same 77-line file and in the same two methods.
Splitting them across waves would produce a partial fix that looks complete in a diff review
(RESEARCH.md Pitfall 3), so `displayServer.ts` is rewritten once, coherently.

Output: a new shared allow-list module, a new config key with production fail-fast, a gated
`/display-screen`, a rewritten `DisplayServer`, and two test files covering both layers.
</objective>
