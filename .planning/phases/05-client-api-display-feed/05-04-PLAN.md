    A new `describe` block in `test/logging-mask.test.ts`, pure unit, no server:
    - The exact log-line templates `agentServer.ts` builds from a connection id survive
      masking unchanged: for a freshly generated id, `mask('Agent connected: ' + id)` equals
      the input, and `mask('Agent WS replaced: ' + a + ' displaced by ' + b)` equals its input.
    - The structural property, stated directly: a generated id contains no run of two adjacent
      digits — assert with a pattern for two consecutive digits and expect no match. This is
      strictly stronger than "no run of seven", so the phone pattern's threshold can never be
      reached however large the timestamp or the sequence number grows.
    - Two ids generated in the same process are different from each other.
    - Two ids generated in two different simulated process lifetimes — sequence counter reset
      to its initial value, clock advanced — are different from each other. This is the second
      half of ledger item 5: ids used to repeat across restarts once the timestamp was masked
      away.
    - A control case proving the fix is load-bearing: the *unreformatted* form of an id built
      from a 13-digit timestamp does NOT survive masking. Build that string locally in the
      test; do not call production code to produce it.
  </behavior>
  <action>
    At the id mint in `agentServer.ts`, apply a digit-run-breaking transform to the assembled
    id string so no two digits are ever adjacent — the same technique
    `test/logging-mask.test.ts:87-89` already uses for synthetic test ids, promoted from the
    test file into production. Insert a non-digit separator between each pair of adjacent
    digits across the whole id, not just the timestamp portion, so a sequence number that
    eventually grows past six digits is covered by the same guarantee. One expression; do not
    introduce a helper module for it.

    Put a comment above the mint stating three things: that the transform exists so the log
    masking filter's phone pattern can never match the id, that the guarantee is that no two
    digits are adjacent rather than that the id is under a length threshold, and that the
    alternative fix — loosening the masking pattern — was explicitly rejected because
    under-masking a real phone number is a strictly worse failure than over-masking an id.
    Reference `docs/OPS-RUNBOOK.md` §7 as the place the operator-facing description of this id
    lives, and note that it needs updating when this ships.

    Change nothing else in `agentServer.ts`: not the authentication check, not the heartbeat
    timings, not the replacement policy, not the disconnect handler, not any message shape.
    The id is used for logging and for the self-comparison guard in the close handler; the
    transform is applied once at mint time so both uses see the same value and that guard's
    behaviour is unchanged.

    Add the `describe` block from `<behavior>` to `test/logging-mask.test.ts`. To exercise the
    two-process-lifetime case without a real restart, construct two `AgentServer` instances
    rather than reaching into private state.
  </action>
