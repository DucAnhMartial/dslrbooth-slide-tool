  <what-built>
    The Agent is now a Windows desktop application. Its core is unchanged — the same WebSocket
    relay, the same trigger server on port 3001, the same in-memory config pull from the CMS, and
    the same 31 tests still pass — but it is now hosted inside an Electron main process with a
    window instead of a terminal. First run offers to import the `.env` that is already on the booth
    PC, so no token is retyped. The window shows connection state, whether dslrBooth is listening,
    and a live tail of the log the Agent already writes. Start and Stop are buttons. Closing the
    window minimizes to the system tray with the relay still running; Quit lives in the tray menu.
    Start-with-Windows is a checkbox, on by default. Secrets never reach the window: it is told
    whether each is set, never what it is, and they are wrapped by Windows' own key store at rest.

    Everything above is proved by the automated suite as far as a Linux machine with no display
    server can prove it. What no test in this environment can reach, and what this gate exists for:
    the application actually launching on Windows, the unsigned-application warning, the tray, the
    login item surviving a reboot, and a real photo flowing end to end. The artifacts are unsigned —
    there is no certificate in this phase's scope — so Windows will warn, and on a machine with
    Smart App Control enabled it will refuse with no override at all.
  </what-built>
  <how-to-verify>
    Please do these in order, between events, with nobody waiting to be photographed. Steps 1 and 3
    are the ones that protect the booth; the rest are the phase.

    1. **Before anything, check Smart App Control.** On the booth PC open Settings → Privacy &
       security → Windows Security → App & browser control → Smart App Control. If it is ON, stop
       here and tell me. An unsigned application cannot be run past it and the fix is a Windows
       setting, not a build change. If it is OFF or in evaluation, continue.

    2. **Note how the Agent runs today**, so you can put it back: whether it is the
       `dslrbooth-agent.exe` started by hand, or the `dslrBooth Agent` Windows service. Either way
       the old one is your rollback and the runbook has the steps.

    3. **Stop the current Agent.** It is holding port 3001, which the new application needs. If you
       skip this, the new one will tell you the port is in use rather than crashing — but it will
       not relay.

    4. **Install.** Run the installer. Windows will show "Windows protected your PC" — click **More
       info**, then **Run anyway**. Tell me the exact wording you see; the runbook's description of
       this screen is from documentation, not from anyone's eyes, and yours is the first look. If
       the installer instead does nothing at all when double-clicked, with no dialog, stop — that is

    10. **Optional, only if you want it today:** uninstall and reinstall, or try the portable

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build machine → booth PC | An unsigned artifact crosses a physical or network channel and is then executed with the operator's privileges |
| Docker image → build output | A third-party image produces the binary that will run on the booth PC |
| runbook → operator action | A wrong or incomplete documented procedure becomes a production mistake mid-event |
| the new application → the running Agent | Two Agents on one machine contend for the trigger port |
