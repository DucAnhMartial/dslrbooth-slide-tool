<objective>
Bring the live, non-restarted failure paths under the same bounded retry policy that plan 02-01
built for the restart path: the `busyTimer` expiry that is BTH-02's safety net, and the Agent
NAK. Both currently requeue a job forever, and both write a timestamp column describing
something that never happened.

Purpose: today `startBusyTimer()`'s callback requeues a timed-out job with no retry counter and
stamps `acknowledged_at` with the current time even though the timeout means the job was never
acknowledged, and the NAK branch stamps the session-start column even though no session started.
Unlimited retry lets one poisoned job block every guest behind it forever — the exact failure
D-05 and D-07 exist to prevent.

Output: a `startBusyTimer` timeout callback and an `onAgentAck` NAK branch that both route through
`handleStall()`, with the two semantically wrong timestamp writes removed, and a fake-timer test
suite that drives a job through the full three-attempt budget to its terminal `failed` state.

**Scope decision on the two pre-existing bugs RESEARCH.md flagged (Pitfall 4): both are IN
SCOPE and both are fixed here.** They are not being fixed opportunistically — both live at the
exact two call sites this plan is already replacing, and `handleStall()` takes no timestamp
parameter at all, so leaving either write in place would mean deliberately re-adding a line the
new code path does not need.

**Repository note:** all git operations must be run inside `mirror-request/`; the workspace root
is not a git repository, and `.planning/` sits outside it and cannot be committed.
</objective>

## Trust Boundaries
