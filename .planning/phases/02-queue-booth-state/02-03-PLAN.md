<objective>
Make the FIFO guarantee observable and prove the two ordering promises this phase must not
break: a requeued guest keeps their place, and one registration can never become two jobs. Then
write down the booth state machine and the operator procedure for a stuck or failed job, so the
`stall_reason` this phase started recording is actually actionable.

Purpose: M2's first success criterion asks for registrations "logged with position numbers" and
nothing in the service logs a queue position today — `getQueuedGuestSummaries()` computes
positions but sends them only to the display feed. D-12 owes an end-to-end proof that the new
retry path cannot duplicate a job. And D-08 makes recording `stall_reason` precisely enough for
an operator to act on it this phase's explicit obligation, which is worth nothing if nobody
documents what the values mean.

Output: one log line at the single enqueue choke point both ingestion paths already share, two
storage-level test files pinning the ordering and idempotency guarantees against real SQL, and
two new sections of `docs/OPS-RUNBOOK.md`.

**Repository note:** all git operations must be run inside `mirror-request/`; the workspace root
is not a git repository, and `.planning/` sits outside it and cannot be committed. This plan is
also where the Phase 2 environment variables get documented, because this execution sandbox
denies all read and write access to `.env*` paths — `docs/OPS-RUNBOOK.md` is the reachable
substitute, and Phase 1 already established it as the place operators look.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ingestion (webhook and DB poller) -> `LocalStore.enqueueJob()` | Externally originated registration ids reach the queue and now reach a log line |
