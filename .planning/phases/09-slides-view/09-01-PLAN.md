<objective>
Grow a second view out of the one room screen: `/display-screen?view=slides` renders the photo
surface alone, at full width, with the queue column gone — and the bare URL that real TVs are
already pointed at renders exactly what it rendered yesterday. Alongside it, the two per-event
toggles (`show_guest_name`, `hero_enabled`) land on the `event` table, in `EventConfig`, on the
wire, and in both views' render paths, both defaulting ON so nothing visibly changes until an
operator decides otherwise.

Purpose: the operator asked for a screen that is only the photos. D9-01 makes that a query
parameter rather than a screen identity, which keeps Phase 8's D-12 ("screens have no identity")
intact — nothing is registered, nothing is stored per screen, every screen still renders the
active event, and only which REGIONS are drawn differs. D9-02 makes the bare route a regression
pin rather than a feature: the service is live, the physical cutover already happened, and every
commit in this plan must leave the tree releasable.

Output: two new `event` columns behind the repo's `PRAGMA table_info()` migration idiom, two new
`EventConfig` fields, a new `src/display/slidesPage.ts`, the view branch in `app.ts`, both
toggles honoured on both views, and three test files pinning the new behaviour and the old.
</objective>
