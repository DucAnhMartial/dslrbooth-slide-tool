<objective>
Build the spine of Phase 8 end-to-end: the SQLite tables that make configuration durable
(CMS-03), the two-layer gate that puts the operator console behind IP allow-list then password
(CMS-04, D-13, D-14), and the single-active-event pointer that lets one server drive several
saved events and every screen at once (CMS-02, D-01, D-12) — proven by one runnable path from
CMS login through event activation to a live WS /display snapshot and the room-screen shell
that applies it.

Purpose: every other plan in this phase writes into a seam this plan creates. Proving the whole
vertical on the first commit is what stops an architectural dead-end from being discovered after
ten committed layers. It also front-loads the two genuinely new primitives (password hashing,
file serving) that have no in-repo precedent.

Output: four new SQLite tables and their store methods, four new config keys, `src/cms/`
(gate, auth, router, pages, event routes, upload serving), `DisplaySnapshot.eventConfig`, the
room-screen config applier, all `index.ts` wiring for the phase, and an offline password-hash
helper.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator laptop → `/cms/*` | Untrusted HTTP crossing into mutating configuration routes; two controls (network allow-list, session identity) must both hold |
| browser → `GET /uploads/:filename` | Attacker-influenceable path segment crossing into filesystem lookup and Content-Type selection |
| `.env` → process | The operator credential enters as a hash; a plaintext value here is itself the vulnerability |
| LAN → session cookie | No TLS terminates anywhere in this deployment; the cookie crosses the wire in the clear |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Spoofing | `POST /cms/login` credential check | high | mitigate | `scryptSync(pw, salt, 64, {N:16384,r:8,p:1})` + `timingSafeEqual` with a length guard, copied from `agentServer.ts:46-57`; identical generic failure copy for unknown-user and wrong-password so the response is not an account oracle |
| T-08-02 | Elevation of Privilege | `/cms/*` access control | high | mitigate | `createCmsIpGate(CMS_IP_WHITELIST)` mounted strictly before `createCmsRouter`, then `requireSession()` inside it; both layers proved independently live in `test/cms-access-control.test.ts` |
| T-08-03 | Tampering / EoP | `GET /uploads/:filename` | high | mitigate | `path.basename()` before any filesystem access; serving only from `CMS_UPLOAD_DIR`; fixed allow-listed `Content-Type` from a hard-coded four-entry map; no static-file middleware on this path; `.svg`/`.html`/`.js` unreachable by construction |
| T-08-04 | Information Disclosure | session cookie on a TLS-free LAN | medium | accept | `Secure` cannot be set without TLS or the operator can never log in (RESEARCH Pitfall 3); residual exposure bounded — not removed — by `CMS_IP_WHITELIST`; the acceptance and its reason are stated in the cookie-setting code and carried into the runbook by plan 08-06 |
