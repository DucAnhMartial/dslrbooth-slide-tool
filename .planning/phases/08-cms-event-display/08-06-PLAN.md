publish the operator documentation for everything this phase adds, mark `web-slide` retired in

  <name>Task 3: The physical cutover and the room screen on a real TV</name>
  <what-built>
    The room screen now lives inside the Extension Service at its own route, driven by the one
    feed that knows the queue, themed by the active event's configuration, with a hero moment for
    the guest who just finished, durable per-event photo history, an operator console behind an IP
    allow-list and a password, and remote configuration of the Agent's four safe fields. The
    automated readiness probe in Task 1 has proved that whole path end to end against a temp
    database. `web-slide` has been marked retired in its own repository but is still whatever it
    was in production — nothing has stopped it, and no TV has been re-pointed.
  </what-built>
  <how-to-verify>
    This gate is physical and cannot be settled from code. Please do these in order, between
    events — never during one. D-06 chose a hard cutover with no redirect shim, so there is no
    fast rollback: if the new screen misbehaves mid-event, someone walks to every TV.

    1. **Identify the supervisor.** Tell us how `web-slide` is currently kept running in
       production — PM2, systemd, a Docker container, a terminal someone left open, or something
       else. This repository contains no process-manager configuration for it, so this is the one
       fact the code genuinely cannot answer. If it is under a supervisor and only the process is
       killed, it will come straight back and keep serving stale content on its old port.

    2. **Stop it, and stop its supervision.** Then confirm the old URL no longer answers.

    3. **Re-point each TV** to the service's room-screen route — the same URL for every screen,
       which the CMS shows as a copyable string. Confirm each TV renders the idle standby screen.

    4. **Judge the screen at real viewing distance.** Stand where guests stand. Is the idle
       heading legible from meters away? Do Vietnamese diacritics render correctly at hero size?
       Does "nobody yet" clearly look different from "broken"? This is UI-01's real test and no
       automated check substitutes for it.

    5. **Optional but valuable if an Agent is connected:** run one real capture and confirm the
       guest sees their own photo and name fill the screen, then watch it join the slideshow.

    Report back what you did, what you declined, and anything that looked wrong. A declined step
    is a legitimate answer and will be recorded as declined rather than passed — this project's
    precedent is to record `human_needed` over claiming a blanket pass.
  </how-to-verify>
