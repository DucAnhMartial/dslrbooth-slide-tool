<objective>
Give the operator the durable photo history CMS-03 promises — per event, newest first, paginated,
with thumbnails that degrade gracefully — and exactly one way to delete it: by hand, with
confirmation.

Purpose: `web-slide` held guests in a 50-entry in-memory array that vanished on every restart.
This is the surface that replaces it, and the one place in the system where deletion of real
guests' photographs is possible at all — so the deletion path is deliberately narrow and loud.

Output: the photo-history page, its pagination, its clear-history action, and its failure states.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser → `POST /cms/api/photos/clear` | An irreversible destruction of real guests' records crosses here |
| stored photo URL → CMS `<img src>` | A URL recorded from the Agent is rendered in the operator's browser |
| guest names → log stream | PII crosses into files that are rotated and retained |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-25 | Information Disclosure | guest names in photo-history log lines | high | mitigate | Every log line is a template string through the labelled logger so the winston masking formatters run; the clear action logs an id and a count and no name; a test spies on the logger and asserts every argument is a string |
| T-08-26 | Tampering / Destruction | accidental or forged history deletion | high | mitigate | Behind both CMS-04 layers plus a typed confirmation; scoped to one event id; `SameSite=Lax` blocks cross-site submission; no automatic deletion path exists anywhere for a forged request to piggyback on |
| T-08-27 | Information Disclosure | one event's photos visible under another | medium | mitigate | Every read is scoped by event id through the store projection; a test asserts cross-event isolation on both listing and clearing |
| T-08-28 | Denial of Service | unbounded history rendering the whole table | medium | mitigate | Fixed 50-row pagination server-side; D-11 deliberately places no bound on the table itself, so the bound lives at the query and the render |
| T-08-29 | Information Disclosure | internal photo-row columns leaking into the page | low | mitigate | Reads go through `listEventPhotos`'s projection rather than raw row access, mirroring the display snapshot's own no-raw-rows discipline |
| T-08-SC | Tampering | npm installs | low | accept | Zero new packages; pagination, confirmation and the placeholder are template-string HTML with no dependency |
</threat_model>
