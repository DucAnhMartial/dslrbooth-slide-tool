Apply the cutover to the live production MySQL server, with a human's explicit
yes, and prove afterwards — through the service's own credentials — that the
ingestion seam reads, cannot write, and starts from the right place.

has no undo in MySQL; the only path back is the artefact plan 06-04 captured.

`auto_advance` is unset), and this gate is the most consequential of them.

process starts) and stages D-07 (the end-to-end proof is a real registration made
live during the cutover, run at plan 06-06's gate — never a replay). D-02 still
holds throughout: no source file changes here.

Output: two live VIEWs, one read-only grant, a seeded cursor, a running service,
and the observed result of every check recorded in the SUMMARY.
</objective>
