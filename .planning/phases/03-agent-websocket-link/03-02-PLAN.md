<objective>
Harden the Agent transport's observability and liveness on top of the authenticated socket
plan 03-01 established: name both parties when one Agent displaces another, make connection ids
collision-proof, make the heartbeat watchdog testable and test it, and expose the disconnect
seam that plan 03-04's requeue policy will bind to.

Purpose: three gaps, all read from live source this session. A newly connecting Agent silently
closes the incumbent with no log on either side (`agentServer.ts:44-46`), so two Agents
misconfigured onto one server produce an invisible flap. Connection ids are minted as
`agent-${Date.now()}` (line 47), so two connections accepted inside the same millisecond — which
a test that connects twice in a row will routinely produce — share an id and defeat the close
guard on line 81 that everything else in this phase depends on. And AGT-05's heartbeat watchdog
(lines 127-139) has **zero** test coverage today, because its interval is a module constant that
no test can shorten.

Output: a displacement warning naming both ids; a monotonic id suffix; an `AgentServer`
constructor that accepts heartbeat timing overrides while defaulting to today's production
values; a `registerDisconnectHandler` seam fired from both real disconnect paths and from neither
stale one; and the first two automated tests this transport has ever had for replacement and
liveness.

**Scope boundary.** This plan changes `agentServer.ts` only. It does not touch `queueService.ts`
— the disconnect handler registered here defaults to a no-op, and plan 03-04 binds the real
policy to it. That split is deliberate: it keeps this plan and plan 03-03 free of file conflicts
so both can run in wave 2.

  <action>
1. `mirror-request/src/agent/agentServer.ts` — add a private field and a registration method
   beside the existing ack/event pair, in the identical shape:

   ```ts
   private disconnectHandler: () => void = () => {};

   registerDisconnectHandler(fn: () => void): void { this.disconnectHandler = fn; }
   ```

   Default it to a no-op function, never to `null` — every call site then invokes it
   unconditionally with no null check, exactly as `ackHandler` and `eventHandler` already work.

2. Add the call **inside** the existing close guard, after the existing info line:

   ```ts
   ws.on('close', () => {
     if (this.agentConn?.id === id) {
       this.agentConn = null;
       logger.info('Agent disconnected');
       this.disconnectHandler();
     }
   });
   ```

   It must stay inside `if (this.agentConn?.id === id)`. When a second Agent displaces the first,
   the server closes the old socket *before* reassigning `this.agentConn`, and the old socket's
   `'close'` fires asynchronously afterwards — by then the field holds the new connection, so the
   guard makes the stale close a no-op. Task 1's monotonic id suffix is what keeps that guard
   sound when both connections land in the same millisecond. Hoisting this call outside the guard
   would let a displaced socket unwind a session belonging to the Agent that replaced it.

3. Add the same call to the heartbeat watchdog's eviction branch, immediately after
   `this.agentConn = null;`:

   ```ts
   this.agentConn = null;
   this.disconnectHandler();
   ```

   This second call site is required, not optional. The watchdog nulls `agentConn` before the
   socket's own `'close'` event can fire, so that later event finds the guard false and calls
   nothing — meaning that without this line, the most common real-world dead-booth case (an Agent
   whose machine lost power, so no clean TCP close ever arrives, only the heartbeat lapse) would
   never reach the handler at all, and the guest would still wait out Phase 2's full session
   timeout. Placing the call after the null assignment also guarantees exactly one invocation
   across the eviction-then-close sequence, and guarantees any handler that reads
   `isAgentOnline()` sees a consistent offline state.

4. Change nothing else. Do not add a state check to the eviction branch, do not add a second
   guard to the close handler, and above all do not import anything from `queueService.ts` here —
   `AgentServer` stays a transport that knows only that a socket closed. Deciding what that means
   for an in-flight job is `QueueService`'s job, bound through this seam in plan 03-04.
