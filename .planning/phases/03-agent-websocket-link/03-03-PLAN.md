<objective>
Stop the queue feeding guests into a booth that is not there, and make the dispatch command
carry what the guest actually registered for.

Purpose: two confirmed defects, both read from live source this session.

First, `dispatchJob()` (`queueService.ts:211-218`) marks the job `dispatched`, sets the booth
`BUSY`, arms the five-minute timer and calls `sendCommandCb` **unconditionally**.
`AgentServer.sendCommand()` does return `false` and log a warning when there is no connection
(`agentServer.ts:112-119`) — but the callback binding in `createQueueService()` discards it, and
the callback's own type is `void`, so nothing upstream can react. The result is a command sent
into the void followed by a full five-minute retry cycle spent waiting for an acknowledgement
that cannot arrive. This is the most likely cause of the four stranded jobs of 2026-08-06, and
under Phase 2's bounded budget it now also *fails* the guest: three booth outages and a
perfectly valid registration is marked `failed`. D-01 forbids exactly that.

Second, and not covered by any D-number — research surfaced it while reading the same function.
AGT-02's payload contract is `{type, action, jobId, mode}`, but `dispatchJob()` composes
`{ type, action, jobId }` and stops (`queueService.ts:216`). `JSON.stringify` drops the missing
key, and the Agent falls back to its own hardcoded default (`dslrbooth-agent/src/index.ts:70`,
then again in `dslrbooth/client.ts:63`). Nothing crashes, and nothing has ever flagged it —
**every session the physical booth has ever run has used the fallback mode, regardless of what
the guest chose at registration.** That is a live correctness bug affecting real guests, and it
is one line of composition away from fixed, because `LocalStore.getJobRegistration()` already
exists and already performs the exact join needed (`localStore.ts:294-305`).

Output: a connectivity gate at both the tick and the dispatch, with once-per-state-change
logging; a dispatch payload that carries the guest's mode; and three new or extended test files
proving all of it.

`agentServer.ts` — that file belongs to plan 03-02 in the same wave, and the two must not
collide. `AgentServer.isAgentOnline()` already exists and is used here unchanged.

