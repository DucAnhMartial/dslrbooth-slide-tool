# Phase 999.1: slide-caption-config - Context

**Gathered:** 2026-08-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Add three per-event CMS settings for the room screen's photo caption: a caption
template, a 9-point position anchored to the photo box, and a photo-fit choice.
All defaults must reproduce the current screen exactly. The setting must apply
to both the slides-only and default room-screen renderers.

</domain>

<decisions>
## Implementation Decisions

### Caption content and safety

- **D999.1-01:** `guestNameTemplate` defaults to `{guest_name}`. Replace every
  literal `{guest_name}` with the guest name; a template without that token is
  valid and produces a fixed per-event sentence.
- **D999.1-02:** Caption text is always inserted with `textContent`, never by
  interpolating into `innerHTML`. The safe render shape is
  `name.textContent = template.replace(/\{guest_name\}/g, photo.name || '')`.
- **D999.1-03:** A long resulting caption may wrap to at most two lines; any
  remaining content is ellipsized. This is the operator's explicit choice.
- **D999.1-04:** Keep the caption as one uniform style. Per-name emphasis
  (such as bold guest names) is out of scope.

### Caption placement and photo fitting

- **D999.1-05:** `captionPosition` defaults to `bottom-left` and offers a
  9-point grid anchored to the photo's own box, never to the full stage. The
  image must therefore be inside a shrink-to-fit wrapper.
- **D999.1-06:** `photoFit` defaults to `contain`, preserving all current
  rendering. The CMS offers three choices: `contain` (keep the full photo with
  letterboxing), `cover` (fill the screen and crop), and `contain_blur` (keep
  the full photo while filling the unused 16:9 space with a blurred version of
  that same photo). `cover` must plainly warn that it is intended for
  landscape frames and can remove event logos or most of a portrait strip.
- **D999.1-07:** Under `cover`, the photo box is the stage, so the caption
  remains over the photo. Derive the dark legibility gradient from the chosen
  caption position; no separate gradient configuration field is added. A
  gradient is unnecessary when `contain` places the caption in a black bar.

### CMS and live display path

- **D999.1-08:** Follow the existing `idleHeading` configuration path end to
  end: `DEFAULT_EVENT_CONFIG`, SQLite mapping and allow-list, EventConfig
  types, additive `event` migration, CMS form, non-null validator, and live
  display projection.
- **D999.1-09:** Apply the visual caption/template/position/fit behaviour only
  to `src/display/slidesPage.ts` (`/display-screen?view=slides`).
  `src/display/displayPage.ts` keeps its current queue/idle-only, no-photo
  role; do not reintroduce photo or caption markup there. The per-event config
  contract still flows through the shared storage and live snapshot path.

</decisions>

<specifics>
## Specific Ideas

- The caption must stay visually attached to the photo: a portrait composite
  on a 16:9 stage should not place its caption in a distant letterbox bar.
- `cover` is intentionally available despite its cropping trade-off; the CMS
  explains it instead of blocking the operator.
- `contain_blur` is for composed 3:2 event frames on a 16:9 TV: the frame stays
  complete while its own blurred image fills the otherwise-black space.

</specifics>
