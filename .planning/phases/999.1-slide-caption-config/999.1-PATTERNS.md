## Scope resolution

`999.1-CONTEXT.md` D999.1-09 is authoritative: visual caption/template/position/fit work belongs only in `src/display/slidesPage.ts`. `src/display/displayPage.ts` is a no-photo/no-caption regression boundary and must not gain a photo builder, slideshow, photo CSS, or caption markup. The shared typed, stored, validated, and live-projected config still reaches every display snapshot through `EventConfig`; the waiting page simply does not dereference these three fields.

The older, verbatim D999.1-09 text in `999.1-RESEARCH.md` saying both pages render names is contradicted by both the later research resolution and the current code/tests. Do not follow that stale premise.

## Pattern Assignments

### `src/types.ts` — typed display contract

**Analog:** `EventConfig` at `mirror-request/src/types.ts:95-152`.

Add non-optional camelCase fields beside the existing display options. Use literal unions for the closed values, not broad optional compatibility strings:

```ts
export interface EventConfig {
  // ...
  showGuestName: boolean;
  backgroundOverlay: number;
  heroEnabled: boolean;
}
```

**Apply:** add `guestNameTemplate: string`, `captionPosition: CaptionPosition`, and `photoFit: PhotoFit` (with 9 exact position literals and `contain | cover`). The contract is deliberately non-null: `LocalStore.getActiveEventConfig()` supplies defaults before `DisplayServer.buildSnapshot()` serializes it.

### `src/state/localStore.ts` — one end-to-end persisted configuration seam

**Analog:** `show_guest_name` / `hero_enabled` through `DEFAULT_EVENT_CONFIG`, `EventRow`, `toEventConfig`, `EVENT_UPDATABLE_COLUMNS`, fresh schema, and `migrate()`.

**Default/projection pattern** (`mirror-request/src/state/localStore.ts:31-134`):

```ts
export const DEFAULT_EVENT_CONFIG: EventConfig = Object.freeze({
  // ...
  showGuestName: true,
  heroEnabled: true,
  backgroundOverlay: 72,
});

function toEventConfig(row: EventRow): EventConfig {
  return {
    // ...
    idleHeading: row.idle_heading ?? DEFAULT_EVENT_CONFIG.idleHeading,
    showGuestName: row.show_guest_name === null
      ? DEFAULT_EVENT_CONFIG.showGuestName
      : row.show_guest_name !== 0,
  };
}
```

Add snake_case raw row members, camelCase defaults, and explicit `?? DEFAULT_EVENT_CONFIG.*` mappings. Even though new columns are `NOT NULL`, keep the read-side fallback for hand-edited/pre-rollout legacy safety.

**SQL allow-list pattern** (`localStore.ts:143-169`, `1485-1497`):

```ts
const EVENT_UPDATABLE_COLUMNS = [
  // literal, reviewed column names only
  'show_guest_name',
  'background_overlay',
  'hero_enabled',
] as const;

const columns = EVENT_UPDATABLE_COLUMNS.filter((column) =>
  Object.prototype.hasOwnProperty.call(patch, column),
);
const assignments = columns.map((column) => `${column} = ?`).join(', ');
const values = columns.map((column) => patch[column] ?? null);
```

Add only literal `guest_name_template`, `caption_position`, and `photo_fit` entries. This is the SQL-injection boundary. Because `updateEvent()` turns nullish values into `NULL`, validation for the three new NOT NULL fields must never return `null`.

**Fresh schema + additive migration pattern** (`localStore.ts:292-323`, `559-573`):

```ts
const eventColumns = this.db.prepare("PRAGMA table_info('event')").all() as Array<{ name: string }>;
if (!eventColumns.some((c) => c.name === 'background_overlay')) {
  this.db.exec('ALTER TABLE event ADD COLUMN background_overlay INTEGER NOT NULL DEFAULT 72');
}
```

Declare all three new fresh-table columns as `TEXT NOT NULL DEFAULT ...`, then make three conditional `ALTER TABLE ... ADD COLUMN` operations from the same single `eventColumns` read. Defaults must be `{guest_name}`, `bottom-left`, and `contain`, so an old event renders exactly as it did at migration time.

### `src/cms/cmsEventPages.ts` — form, tag map, and warning copy

**Analog:** `FIELD_SCREEN_MAP` (`cmsEventPages.ts:480-501`), generic `textField()` (`518-525`), and the photo-settings block around `705-721`.

function textField(opts: { name: string; label: string; value: string; maxlength: number; hint?: string }): string {
  return `<div class="field">
    <label for="${opts.name}">${opts.label}${screenTag(opts.name)}</label>
    <input id="${opts.name}" name="${opts.name}" type="text" maxlength="${opts.maxlength}"

Escape configuration values exactly as existing template rendering does.

### `src/cms/cmsEventRoutes.ts` — atomic non-null validation

**Analog:** `enumField()` and the existing distinction between nullable `textField()` and required `nameField()` (`cmsEventRoutes.ts:91-135`), then `FIELD_VALIDATORS` (`170-190`).

```ts
function enumField(values: readonly string[]): FieldValidator {
  return (raw) => (typeof raw === 'string' && values.includes(raw) ? raw : undefined);
}

const nameField: FieldValidator = (raw) => {
  if (typeof raw !== 'string') return undefined;
  const trimmed = raw.trim();
  if (!trimmed) return undefined;
  return trimmed.length <= FIELD_CAPS.name ? trimmed : undefined;
};
```

Create a required trimmed capped text validator for `guest_name_template`: reject missing, empty, non-string, and oversize values with `undefined`; do not use `textField()`, which returns `null` for a clear action. Use exact enum validators for the 9 position tokens and `contain`/`cover`. Add the three named validators to `FIELD_VALIDATORS`; existing patch validation rejects the entire request if any recognized field yields `undefined`, preventing partial writes.

### `src/display/slidesPage.ts` — frame-local safe caption rendering

**Analog:** `shotTile()` (`slidesPage.ts:261-307`) and per-snapshot module-level values (`342-400`).

```js
function shotTile(photo,badgeText){
  var slide=document.createElement('div');
  slide.className='slide';
  var img=document.createElement('img');
  img.alt='';
  img.src=photo.photoUrl;
  slide.appendChild(img);
  if(guestNameEnabled){
    var name=document.createElement('p');
    name.className='shotname';
    name.textContent=(photo&&photo.name)||'';
  }
}

function render(data){
  var cfg=data.eventConfig||{};
  heroTakeoverEnabled=cfg.heroEnabled!==false;
  guestNameEnabled=cfg.showGuestName!==false;
}
```

Retain the DOM-API construction style and the single static `innerHTML` broken-image fallback, whose dynamic message is assigned by `textContent`. Introduce live config state on every `render()` with exact validation/fallbacks; do not turn untrusted config into a CSS selector/class. `shotTile()` must construct a shrink-to-fit, `position:relative` photo frame containing image and caption, then append it to `.slide`. The caption's only text assignment is:

```js
name.textContent=template.replace(/\{guest_name\}/g,(photo&&photo.name)||'');
```

Use a controlled class or data attribute from the validated nine-token set to position the caption. CSS must preserve `contain` as the default/current behavior, use two-line `-webkit-line-clamp` rather than `nowrap`, and switch to stage-sized `object-fit:cover` only under `cover`. Derive cover-only legibility gradient classes from the trusted normalized position; do not add persisted gradient configuration. Keep badge creation as a separate DOM child.

## Shared Patterns

### Naming and boundary conversion

- CMS request and SQLite: snake_case (`guest_name_template`, `caption_position`, `photo_fit`).
- Display contract and browser config: camelCase (`guestNameTemplate`, `captionPosition`, `photoFit`).
- Convert only in `toEventConfig()`; do not expose raw event rows or add ad-hoc mapper logic in display code.

### Live update behavior

`DisplayServer.buildSnapshot()` calls `getActiveEventConfig()` each snapshot and `maybeBroadcast()` emits only when serialized content changes. Slides code must refresh its derived values in every `render(data)`, matching the existing `heroTakeoverEnabled` / `guestNameEnabled` pattern instead of capturing settings once at load.

### Safety

- CMS enum values are rejected, not coerced; the allow-list controls SQL column names and all values remain bound parameters.
- Caption template and guest name are untrusted. Insert the final string with `textContent` only; no token/name/template interpolation into `innerHTML`.
- Only construct CSS position/gradient classes after exact whitelist validation with a shipped fallback.

### Default preservation

The fresh schema, additive migration, default object, and read-time coalescing must agree on `{guest_name}`, `bottom-left`, and `contain`. `contain` preserves the current image behavior and black stage; the new frame changes caption anchoring without moving it to the full-stage letterbox.
